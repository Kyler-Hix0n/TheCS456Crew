checkpointing.py (Tasks 1 & 2 - State Sync):
to handle state preservation. It runs a background thread on the Primary firewall that saves our current BLACKLIST array to a local file (firewall_state.json) every n seconds. This way, when the Secondary firewall boots up, it just reads this file and loads the exact same blacklist the Primary had right before it crashed.

firewall.py (Tasks 1 & 2 - Replica Process):
We need to update our firewall script to accept command-line arguments so it knows whether it’s running as the PRIMARY (on port 8001) or the SECONDARY (on port 8002). We also need to modify the UDP heartbeat to include its role (e.g., b"HEARTBEAT:PRIMARY") so the monitor always knows exactly which node it's talking to.

monitor.py (Task 3 - Automated Failover):
Instead of just printing a red alert when the primary dies like in Part 1, our monitor will now need to actually handle the recovery. We need to add a start_secondary_node() function so that after 3 missed heartbeats, it uses Python's subprocess module to automatically spin up a new firewall.py instance on port 8002. We also made sure it checks the role tag in the heartbeats to prevent "split-brain" syndrome, meaning it will safely ignore any delayed packets from a dead primary node.

server.py (The Client):
We could update the web server to act as a basic load balancer. Instead of hardcoding it to only ask port 8001 for a firewall verdict, it could iterate through a list of FIREWALL_URLS. If port 8001 (Primary) times out, it seamlessly routes the client's request to port 8002 (Secondary) without dropping the connection.
